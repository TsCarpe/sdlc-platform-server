## 0. 结论先行

**综合得分：3.4 / 5.0（demo 可用、架构底子好；协作基础设施与质量门是主要短板；无 P0）**

| 维度 | 权重 | 得分 | 一句话结论 |
|---|---:|---:|---|
| A 技术/架构与工程化 | 30% | **3.5** | 分层、事务、并发与安全防护显著优于同规模项目；但 CI 质量门实际是红的，完成回调与 runner 恢复有硬伤 |
| B Skill/Agent 设计 | 25% | **3.5** | 九个 skill 方法论完整、关卡与渐进披露成熟；但「全新上下文对抗」在进程内通道退化，机械关卡存在自证面 |
| C 产品与用户 | 25% | **3.0** | 主旅程闭环与红线主逻辑扎实；但两个 P1 功能缺陷 + 协作基础设施缺失，使「团队协作平台」只兑现一半 |
| D UI/UX 与视觉 | 20% | **3.4** | 视觉完成度高、状态设计成熟；但工作台首屏藏题、流水线面板挤压页签、响应式缺失，可访问性为系统性欠账 |

**最该先做的六件事**：
1. **把质量门修绿并真正阻塞**：server（ruff/pyright/pytest）、skills（断链 + Pillow）、跨仓契约测试的 CI 可运行性。
2. **补齐写令牌全链路**：web 所有 fetch（含 SSE/上传）注入 `X-Token`，否则一旦启用写保护，前端全部写操作 401。
3. **修 source_import 完成回调的「先副作用后终态校验」**：先原子抢占终态，再执行全量块替换；否则迟到/重复 done 会覆盖平台数据。
4. **修 runner 恢复归属**：`local-<pid>` 重启即变名，旧 running 任务永久悬挂；需要稳定 runner 名或服务端周期 sweeper。
5. **修两个产品 P1**：表单用例永久 draft 堵死 GR-2；GR-3 用 `>=` 把「无变化」判成「已变更」。
6. **修工作台首屏与布局**：分组默认展开、流水线面板下移为摘要条、补 1200/900/760 响应式断点。

**最重要的正面结论**：上一轮 `AUDIT-2026-10.md` 的四个 P0（写令牌绕过、媒体 XSS、409 死代码、备份死脚本）已全部修复且经本轮复核确认；架构、并发、安全与验收链的底子很好，问题主要是「最后一公里」的工程收口与协作能力，而非结构性返工。

## 3. P1 清单（建议本迭代内修复）

### P1-1 server 五道质量门在 main 上持续红灯
- 证据：GitHub run `39102758345`（2026-10-18）第一步 `uv run ruff check` 因 `src/platform_sdlc/services/requirement.py:27` 的 F401 失败；同 job 后续 pyright（17 errors）、pytest、`check_task_templates`、`export-openapi`、快照 diff 全部不执行。`.github/workflows/ci.yml:15-27`。
- 影响：质量门从未真正守住；ruff 一红掩盖全部信号；「pyright 已清零并转阻塞门」的承诺已回退。
- 建议：修 F401；清零 pyright（tests 可精确豁免）；步骤拆独立 job 或 `if: always()` 让每道门都出报告；分支保护要求这些 check。

### P1-2 跨仓契约测试非 hermetic，server CI 天然不可绿
- 证据：`tests/test_v5_clarify.py:254-255,498-505,542-557` 直接读 `~/IdeaProjects/claude-sdlc-skills`，缺失即 `pytest.fail`；CI 只 checkout server。本地因 skills 去版本标注（`payload-schema.md` 首行变为 `# sdlc-sync payload 契约`）而断言失败。
- 影响：server 单仓 CI 永远无法自然转绿；契约测试从「守门」变成「本地环境探测器」。
- 建议：仓内 vendor 契约快照，或 CI 显式 checkout 固定 ref + env；断言结构键（options/module/layer/pids/answerText）而非人类文档版本串；版本号入独立 `contract-version.json`。

### P1-3 skills CI 连续失败 17 次
- 证据：最后一次成功 2026-09-28；`docs/faq.md:58` → `../poc/jev-ultrafast/README.md`，而 `.gitignore:21` 排除 `poc/`；`validate.yml:48-73` 断链零容忍。另 `validate.yml:139` 跑 `compare.py --self-test`，但无 `pip install Pillow`；`compare.py:39-40` 缺依赖 `exit 2`。
- 影响：skills 仓 20 步校验长期未执行，规范问题持续累积；本地与 CI 结果不一致。
- 建议：删除该链接或改为仓内决策记录；断链检查只遍历 `git ls-files`；CI 显式安装 Pillow 或 self-test 延迟 import；description 压到 ≤900 bytes。

### P1-4 Web 全链路无写令牌，启用 `SDLC_WRITE_TOKEN` 即全站写失败
- 证据：`sdlc-platform-web/src/api.js:1-17` 的 fetch 只带 `Content-Type`；`uploadMedia`（`:23-32`）只带 `x-media-mime`；`Chat.vue:33-37` SSE fetch 与 `:71-75` 清会话均无令牌；全仓 `grep X-Token` 零命中。服务端 `main.py:107-121` 对所有非 GET `/api` 强制校验。
- 影响：设置令牌后建卡、排任务、采纳、上传、助理、清会话全部 401；实际部署只能保持令牌为空，写面完全开放。
- 建议：统一 fetch 包装注入 `X-Token`，覆盖 uploadMedia 与 SSE；`verify-token` 增 Web 端到端；或改同源 HttpOnly cookie。

### P1-5 外置 runner 恢复按 PID 名归属，重启后旧任务永久 running
- 证据：`runner/runner.mjs:24` 默认 `RUNNER=local-${process.pid}`；`scripts/runner.sh` 未设 `SDLC_RUNNER_NAME`；`recoverStale()`（`:330-338`）按本进程名过滤；`AgentLoop` 只清 `openai-agents-inproc`（`agent/loop.py:86-91`）；`task_repo.py:129-138` 按 runner 过滤；无周期 sweeper。`recover-stale` 不带 runner 时清全部通道（`routers/tasks.py:43-47`），是唯一手工兜底但会误杀另一通道。
- 影响：runner 每次重启都会留下孤儿 running；同需求同类型新任务被 409 永久挡住，只能人工调接口。
- 建议：runner 名稳定化（env/主机名+角色）或改租约/心跳；服务端周期 stale sweeper（仅清心跳丢失者）；`recover-stale` 区分本通道/全量并要求显式参数。

### P1-6 source_import 完成回调先副作用后终态校验，且无 attempt fencing
- 证据：`services/task.py:159-190` 先 `find`，未校验 `t.status/t.runner`，对 `ok && source_import` 直接调 `import_from_output`；该函数事务内 `replace_all`（`req_block_repo.py:13-23` 先 DELETE 全表再插入）并重建评论（`block.py:277-290`）；最后才 `task_repo.finish(... WHERE status='running')`，失败抛 409。`retry` 复用同一 task id；导入封存守卫只在建任务时检查，导入内无复检。
- 影响：重复/迟到 done 会先完成一次全量替换再得到 409；旧执行器的迟到 done 可把 retry 后的新 attempt 直接置终态；迟到 `failed` 同样可把新 attempt 置 failed（fencing 缺失的对称面）；平台块编辑/评论可被覆盖，违反「导入分源封存」红线。
- 建议：先用条件 UPDATE/claim token 原子抢占终态，成功后再执行导入；导入与终态置位同事务、失败回滚；导入前复检封存条件；done 回调携带 attempt/runner token。

### P1-7 表单来源用例永久 draft，直接堵死门禁 GR-2；且平台无法删除用例
- 证据：`services/case.py:150` `form_create` 固定 `status="draft"`；`test_case_repo.py:88` `update_form` 不改 status；关卡互认只更新 `tool='sdlc-test'`（同文件 `:163-166`）；`gate.py:46-49` 统计全部用例并要求全部 reviewed；`routers/cases.py:18-43` 无用例 DELETE。
- 影响：AI 推 TC + 测试同学表单登记 WEB-xxx 是最自然用法；只要有一条表单用例，门禁永久 409「N 条未定稿」；误建用例只能改库。
- 建议：门禁只统计 `sdlc-test`，或给表单用例人工「定稿」动作；补 DELETE 端点与 UI；GateTab 条件②标注来源。

### P1-8 GR-3 用例变更判定用 `>=`，每次放行后必挂假变更横幅
- 证据：`services/gate.py:297-299` `cur_cases >= str(b.get("casesMaxUpdated","")) and cur_cases`；基线在开闸时记录（`:115-128`）。开闸要求用例 ≥1；放行后无人改用例时 `cur_cases` 与基线相等，`>=` 仍为真。测试与黑盒已承认该分支不可达：`tests/test_guards.py:409-410`、`scripts/verify-gate.mjs:136-140`。
- 影响：任何有用例的需求放行后都会显示「用例在基线后有更新」；用户会开无意义复审轮、白烧 token；且 `reopen` 只看 `changed`，任何有用例的卡都能无变更开 r2；GR-3 信号价值被噪声淹没。
- 建议：改严格 `>`，或基线取放行时刻快照；补「无变更 → changed=false」回归测试。

### P1-9 进程内 gate 的「A=4/B=2 全新上下文」结构性退化，且无扇出留痕
- 证据：`skills/sdlc-gate/SKILL.md:3,45-55` 要求 Agent 工具扇出；`agent/prompts.py:107` 明确降级为「进程内单会话…按各角色逐角色独立过审」；`ALL_TOOLS`（`agent/tools.py:373-374`）无 spawn/Agent 工具；`check_trace/guard_dev` 不校验扇出数；issues 头已有风险分级/来源角色，但无扇出数量与「全新上下文」的可验证留痕。
- 影响：进程内 gate 可能只是单模型顺序自审，与真实 4 子代理评审不可区分；即便外置 runner，模型跳过子代理也无人校验。
- 建议：草稿/UI 标注「降级评审」；A/B 强制外置 runner；扇出数写入 issues 头并机器校验；或将进程内 gate 限定 C 级。

### P1-10 agent `run_command` 继承服务器环境且可联网，存在凭据外泄面
- 证据：`agent/tools.py:350` `subprocess.run` 未传 `env`，完整继承进程环境；`config.py:21,34` 的 `write_token`、`agent_api_key` 来自 env；`_CMD_ALLOW` 含 `python3/node/curl`（`tools.py:26`）；无文件系统/出网沙箱；agent 输入含外部需求原文与评论。
- 影响：需求文档/评论中的 prompt injection 可让 agent 用 `python3` 读 env/用户目录，再用 `curl` 外发 token 与模型 key。**若接入外部需求源或公网，应升级为 P0。**
- 建议：子进程用显式环境白名单；任务进受限容器/低权用户 + 出网白名单；移除 `curl` 或走代理；输出脱敏。

### P1-11 澄清工作台所有分组默认折叠，首屏只剩组头
- 证据：`sdlc-platform-web/src/composables/group-collapse.js:11` 初始化为空 Set；`WorkbenchTab.vue:501` 以 `!openGrps.has(g.name)` 控制折叠；设计稿 `design-mock/index.html:181-190` 默认展开（仅 `.closed` 才隐藏）。运行时 REQ-2026-010（0/3 已答）首次进入仅见两个组头，问题卡全部不可见。
- 影响：工作台是 v5 的核心页面，首屏却看起来像「没有待办」；与设计稿意图直接冲突，用户需先点「全部展开」。
- 建议：默认展开所有含 pending 的分组（或全部展开），折叠状态按需求 ID 持久化；保留「全部展开/收起」。

### P1-12 流水线 TaskPanel 位于 8 个页签之上，展开时把正文推离首屏

### P1-13 响应式完全缺失：375px 横向溢出，1024px 双栏把问题栏压到约 300px
- 证据：`style.css:1091-1092` 双栏固定 `1fr + 430px`，无窄屏覆盖；`WorkbenchTab.vue:79-82` 以行内 `gridTemplateColumns: minmax(0,1fr) 430px` 兜底，即使加 CSS 断点也会被行内样式覆盖；`style.css:47` 侧栏固定 230px。运行时 375px：`wb-grid` 计算值 `0px 430px`，文档 `scrollWidth=540`，页签条 `scrollWidth=725 / clientWidth=243`；1024px：右栏仍 430px，问题栏仅约 300px。

## 6. 改进路线图

### 0–2 周（Quick Wins，建议按序）

1. **修绿质量门**：server ruff（1 行）→ pyright（17 处）→ 跨仓测试改语义断言/独立 integration job；skills 断链 + Pillow + description 余量。
2. **写令牌全链路**：web fetch/SSE/上传注入 `X-Token`；补 Web 端到端 token 冒烟；或改同源 HttpOnly cookie。
3. **运行时硬伤**：runner 稳定名/周期 sweeper；source_import 先原子抢占终态再导入；`recover-stale` 显式区分通道。
4. **产品 P1**：表单用例定稿/DELETE；GR-3 改严格 `>`；补「无变更 → changed=false」回归。
5. **列表可达性**：`LIMIT` 提升 + q 搜索 + 游标分页；评论角标改批量计数。
6. **数据卫生**：verify 默认独立 DB；清理/隔离演示库；`.gitignore` 加 `tasks/`、`.playwright-mcp/`。

### 1–2 个月（结构性）

1. **契约升级**：高频读接口补 response_model + requestBody → 生成 web 类型；`contract-version.json` + 跨仓 CI。
2. **CI 分层**：unit / integration（含 skills checkout）/ black-box verify-all 三层；`import-linter` 接入；分支保护。
3. **安全加固**：agent 子进程环境白名单 + 容器/低权 + 出网白名单；sourceUrl 白名单；工作区按 reqId 隔离。
4. **任务域模型**：`status/outcome` 显式区分 cancelled/superseded/failed；指标口径统一；L2 失败可见。
5. **备份与恢复**：media + assistant.db + manifest + restore 演练。
6. **前端复杂度与可访问性**：Workbench/TaskPanel 拆分；对比度修复；响应式断点；统一超时。
7. **产品闭环**：artifact 版本历史/diff；导出；全局待办；changed 态数据加载；零问题发布通道。

### 季度（战略性）

1. **身份与协作**：SSO/角色/审计/通知/分配；多人并发保护（clarify 乐观锁）。
2. **产品化能力**：搜索/分页/导出/指标看板；多项目与租户边界；执行汇总回平台。
3. **可运维性**：部署/备份/恢复演练、日志与告警、SLO；agent 通道纳入定期回归（带预算控制）。
